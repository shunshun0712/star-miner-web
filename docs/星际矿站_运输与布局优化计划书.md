# 《星际矿站》运输与布局优化计划书（v0.5 / v0.6）

日期：2026-08-08

## 一、摘要

针对「工业逻辑、游戏逻辑、视觉逻辑三重不通」的批评，分三阶段修复运输线与场景布局：

- **v0.5 必做：方案 A（视觉运输）** —— 让运输线「看起来在运」。
- **v0.5 有余力：方案 B（中心辐射布局）** —— 让场景「符合厂区逻辑」。
- **v0.6 立项：方案 C（运输玩法系统）** —— 让运输线「真的在运、能堵、能升级」。

目标：玩家一眼能看出「矿石从哪来、到哪去、中间经过什么」；运输线从「挂名 buff 建筑」变成有存在感、有玩法空间的设施。

## 二、问题诊断（三重不通）

1. **工业逻辑**：设施一字排开（氦-3 -16 → 星尘 -9 → 运输 0 → 精炼 9 → 能源 18 → 氘-3 15），运输线是孤岛，矿石「凭空消失又凭空出现」，能源站远离负荷中心，采掘器没有「矿区」概念。
2. **游戏逻辑**：运输线只是数值 buff（转运 rate + 缓冲上限），没有运力/拥堵/分段的玩法；瓶颈判定存在但没有可视化。
3. **视觉逻辑**：画面一条线、无纵深、无焦点；运输线橙色平板与其他设施（黑金/紫晶）完全不是一个设计语言。

## 三、方案 A：视觉运输（v0.5 已实施）

- 运输枢纽本体重做：六边形底座 + 金色描边 + 控制塔 + 转运臂，沿用采掘器样板设计语言，替换橙色平板 + 白点。
- 移动物流：主环 8 个货舱单向循环 + 支线货舱（采掘端 → 精炼端）+ 能源球，全部 InstancedMesh。
- 拥堵可视化：`ProductionSummary.transportCongested` 新信号（上游产量 > 运输运力 或 精炼缓冲接近满），驱动货舱变红、卸货臂堆积、轨道发光变红呼吸。
- 数值完全不变（纯视觉）。

## 四、方案 B：中心辐射布局（v0.5 已实施）

- 新坐标：精炼厂中心 (0,0)；能源站 (0,12)；星尘采掘器 (-12,-7)；氦-3 (12,-7)；氘-3 (0,-14)；运输枢纽 (6,0)。
- 轨道：主环（半径 6，环绕精炼厂）+ 4 条放射支线（左下/右下/下方采掘支线、上方能源支线）+ 卸货臂（枢纽 → 精炼厂）。
- 同步项：拾取、设施标签投影、相机初始机位与目标、地面环形指示（轨道本体即指示）。
- 解锁顺序保留：沿用费用阶梯与文案，不做空间引导。

## 五、方案 C：运输玩法系统（v0.6 立项，3~4 天）

### 5.1 分段运力

- 环 + 支线拆成 4 段：左采掘支线、右氦-3 支线、下氘-3 支线、主环 + 能源支线。
- 每段独立运力值并可分段升级（复用指数费用阶梯，每级 +20%）。
- 初始总运力 = 现有 1.0/s 基准（4 段各 0.25/s 起）；三采掘满级时需升 2~3 段才能消化，制造「升采掘还是升运输」决策。

### 5.2 拥堵与回压

- 单段进料 > 运力 → 货舱堆积变红；堆积超阈值 → 该段回压（限制 moved 速度）。
- 精炼缓冲满时同样堆积；溢出矿石保持现有「可售」逻辑不丢失。

### 5.3 模拟 / 渲染边界

- 运力、堆积、回压计算全部放 `core/transport.ts`；renderer 只读 `summary` 驱动货舱/堆积/变色。
- `GameState` 新增 `transportSegments: Record<SegmentId, number>`；`SAVE_VERSION +1`（v6→v7，迁移默认全 1 级）。
- 面板增加分段运力条与分段升级入口（瓶颈段红色高亮 + 箭头）。

## 六、接口变更

- `ProductionSummary` 增加 `transportCongested: boolean`（A 已实施；C 扩展 `segmentLoads`）。
- `SceneSyncState` 同步增加 `transportCongested`（A 已实施）。
- C 增加：`GameState.transportSegments`、`core/transport.ts`、`FACILITIES.transport` 分段运力基准。

## 七、测试与验收

- A：货舱循环、拥堵变红（buffer 满 / 上游>运力）、与采掘器样板视觉一致。
- B：拾取、标签、相机在 1920×1080 与 1280×720 正常、轨道循环流畅。
- C：分段运力单测、拥堵回压单测、存档 v6→v7 迁移、pacing 模拟（运输瓶颈场景）。
- 回归：现有全部单测通过、构建通过、浏览器零报错。
